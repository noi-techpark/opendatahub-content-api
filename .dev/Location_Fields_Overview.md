# Location Fields Overview

Overview of the location / administrative assignment fields (LocationInfo, District, Tourism organization, Area,
Region, Municipality, Ski area) on every datatype, as a basis for unifying them.

Generated by reflection over the class each `odhtype` maps to in `Helper/Generic/ODHTypeHelper.cs`
(`TranslateTypeString2Type`), so inherited properties and interfaces are included. State: 2026-10-21.

## Legend

| Value | Meaning |
|---|---|
| Linked | `LocationInfoLinked` |
| – | field not present |
| (deprecated) | marked with `[SwaggerDeprecated]` |
| Location interfaces | interfaces on the class related to District / LocationInfo / Tourism organization |

Property names are written exactly as in the C# model, the JSON output uses the same casing.

## Datatypes without administrative location

- GPS only: `article`, `eventshort`, `skiregion` (`GpsInfo` / `GpsPoints`); `announcement`, `urbangreen`, `trip`,
  `spatialdata` (`Geo`)
- Nothing: `accommodationroom`, `wineaward`, `odhtag`, `publisher`, `source`, `weather`, `weatherhistory`,
  `weatherrealtime`, `snowreport`, `odhmetadata`, `tag`, `geoshape`

## LocationInfo structure

`LocationInfoLinked` contains `RegionInfo`, `TvInfo`, `MunicipalityInfo`, `DistrictInfo`, `AreaInfo`
(each the `*InfoLinked` variant; `AreaInfo` has no deprecation attribute, see `Deprecation_Migration_Overview.md`).

## Differences to unify

1. **Tourism organization has 5 different names**: `TourismVereinId` (accommodation), `TourismvereinId`
   (municipality, district, area), `TourismorganizationId` (odhactivitypoi), `TourismvereinIds` (experiencearea,
   metaregion, skiarea), `TourismVereinIds` (weatherdistrict) — plus `LocationInfo.TvInfo`.
2. **Ski area has 3 spellings**: `SkiAreaIds` (measuringpoint), `SkiareaIds` (region, tourismassociation),
   `SkiAreaID` (area).
3. **Area**: deprecated `AreaId` still next to `AreaIds` (odhactivitypoi, skiarea); collection types differ
   (`HashSet`, `ICollection`, `List`, `IEnumerable`).
4. **District single vs. list**: `DistrictId` vs. `DistrictIds`; event has both.
5. **LocationInfo**: package uses plain `LocationInfo` instead of `LocationInfoLinked`; skiarea and weatherforecast
   have `LocationInfoLinked` but not `IHasLocationInfoLinked` (skipped by code working on the interface).
6. **Interfaces**: `IDistrictId` and `IHasDistrictId` both exist (accommodation only `IDistrictId`);
   `IHasTourismorganizationId` only on odhactivitypoi.
7. **Duplicated data**: accommodation, odhactivitypoi and venue store `DistrictId` / tourism organization flat **and**
   in `LocationInfo`, the two can drift apart.
